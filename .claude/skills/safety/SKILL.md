# Safety

Pain is not soreness [NA-REC-007]. The athlete chooses how the coach handles a painful region. You ask one screen of clickable questions, write the athlete's choice as one plain line in `athlete/limits.md`, and plan around it by judgment. You never refuse to plan, and you never diagnose.

Today is `TZ=<coach.yaml athlete.timezone> date +%F`.

## Steps

1. **Urgent first.** If the session context says `URGENT STOP`, or the athlete names an urgent warning sign (chest pain, fainting, new numbness or weakness, severe shortness of breath, a sudden severe headache), give the urgent-care text from `engine/safety-text.ts` (`URGENT_CARE_TEXT`) first, keeping every instruction. If the stop file does not exist yet, run `node engine/cli.ts urgent set --term <name> --source answer` (it commits and pushes). Make no training change. Go to step 6.
2. **One question screen.** Ask at most 4 questions in one AskUserQuestion call. All questions in one call are fixed before any answer; a follow-up is a second call. The screen holds, in this order:
   - **One handling question per region** (one or two regions): "<Region>: how should the coach handle it?" with the options "It's fine now: train normally", "Go light and build back slowly", "Avoid loading it for now (the safest choice while it hurts)". Say the caution once, in the option text, never as a refusal.
   - **One side question, shared,** only for regions that have sides (shoulder, elbow, wrist, hip, knee, ankle) and whose side is not known. One region: "<Region>: which side?" with "Left", "Right", "Both". Two regions: "Which side?" (`multiSelect: true`) with "<Region A>: left", "<Region A>: right", "<Region B>: left", "<Region B>: right"; both sides of a region means both of its options are chosen. Leave out the options of a region whose side is known.
   - **One warning-sign question:** "Any of these now?" (`multiSelect: true`) with "New numbness or weakness", "Swelling with heat or redness", "Cannot bear weight", "None of these".
   - Two regions are 4 questions at most: two handling questions, one side question, one warning-sign question.
   - More than two regions: one screen per two regions. The warning-sign question goes on the first screen only.
   - A warning-sign answer other than "None of these": run `node engine/cli.ts urgent set --term "<new numbness, new weakness or other urgent sign>" --source answer` and go to step 1. For swelling with heat or redness, or for not bearing weight, use `--term "other urgent sign"`.
3. **The movements.** By default, the line covers every movement that loads the region. `node engine/cli.ts regions` lists, for each movement pattern, the regions it loads (a side region such as `left-knee` also matches its parent `knee`): use it to know which exercises load the region. Ask a second screen only when you cannot tell, for example "Which movements hurt?" (`multiSelect: true`; Pressing, Pulling, Squatting or lunging, Lifting from the floor).
4. **Write the athlete's choice** as one bullet in `athlete/limits.md` (Read it first; start it from `templates/athlete/limits.md` when it is missing, and replace "None yet."). Use the region, the side and the movements in plain words, the choice, and today's date. When a line for the region exists, change that line. A clinician's rule says so in the brackets ("from my physio").
   - "It's fine now": no line (remove an old line for the region). Write one line in the athlete log: "<region>: athlete reports it is fine; train normally".
   - "Go light and build back slowly": for example `- Left knee: light only, building back slowly: about half the usual squats and lunges, nothing heavy. (since 2026-10-23)`. The `week` skill asks once a week how it felt.
   - "Avoid loading it for now": for example `- Left knee: avoid for now: squats, lunges, leg presses and jumps. (since 2026-10-23)`.
   - Say it in one line, in the athlete's words, for example "Left knee: no loaded deep knee bends for now." (no file path). The Stop hook commits the file; commit it yourself when you go on to plan.
5. **Plan around it, without asking.** The athlete's answer on the screen is the yes for the changes to the days the coach wrote: ask no second question about them. Under the urgent stop, change nothing. When the `today` skill called this skill with the history coverage unknown (its post says `urgent.unknown: true`), change no planned day either: the questions, the answers and the limit (step 4) still count, and the next run with complete coverage plans around the limit. This step's plan writes run only with complete coverage and no urgent stop.
   - For the next 7 days, read the planned days where the plans live (`coach.yaml logger`: Tally, `node engine/cli.ts plans read --week <date>`, or the athlete's tool). Check each day against the new line yourself (use `classify --exercise` and `regions` when you are not sure what an exercise loads). When a line names a body part, run `node engine/cli.ts regions` once to see which movements load it, and count all of them for that line (isolation work too, such as leg curls for the knee).
   - For each day that goes against the new line and that the coach wrote (with Tally: `source` is `mcp` and `userModified` is false): change only what goes against it. Avoid: replace the exercise with one of the same slot that does not load the region (search it with `search_exercises` with Tally), or remove it. Light and building back: lower the sets or the load to what the line says (a weight: `node engine/cli.ts load-under`). Keep the rest of the day as it is. Write it as the `week` skill's step 10 does (read first, `expectedVersion`, read back; `plans write` with files). Read the changed days back and check them against the line again.
   - A day the athlete built or edited (with Tally: `source` is not `mcp`, or `userModified` is true) is protected: never change it without a yes. When protected days go against the new line, ask one question for all of them, for example "Thursday is your own day in Tally, and it has Box Squat. Change it to follow the new line? A) Yes, B) Leave it". A: write those days as above, with `overrideUserModified: true` and `expectedVersion`, for those writes only. B: leave them, and say so in one line. This is the only second question, and only when a protected day goes against the line.
   - Say what changed in one line, for example "Changed today and Thursday: Goblet Squat and Leg Press out, Leg Curl and Hip Thrust in." No changes needed: say nothing about it.
6. **Clear the urgent stop** (live session only). Ask one AskUserQuestion: "Has a clinician seen you about it?" with "A clinician has seen me about it", "It was a false alarm", "Not yet". On the first, run `node engine/cli.ts urgent clear --reason clinician`; on the second, `node engine/cli.ts urgent clear --reason false-alarm`. "Not yet", no answer, or no question tool: the stop stays. Never clear it on your own reading.
7. **"It's better" or "it's gone."** Ask "<Region>: what should the coach do now? A) Train normally again, B) Go light and build back slowly, C) Keep it as it is". A: delete the line. B: rewrite the line as building back (step 4). C: change nothing. Write one line in the athlete log.
8. **Old notes** (setup, the weekly review). When `node engine/cli.ts safety scan-notes` reports pain notes, ask one multi-select: "Which of these still bother you?" with one option per region named, plus "None of these". A chosen region goes to step 2. Log the rest as resolved by the athlete.
9. **Pain from a check-in.** When this skill ran for a pain entry of today's check-in (from the `check-in` skill, or the `today` skill's step 2), the skill that called it appends "- pain handled: <region> <checkin_at>" to the log when this skill finishes. A later check-in with worse pain has a new time, so it comes here again.
10. **Always:** never diagnose, never name a likely cause, and never give medication, supplement, hormone or peptide advice. Say "See a clinician for new pain, pain that gets worse, or pain that does not settle." once per conversation.

Without AskUserQuestion (print mode), or when a call returns no answers, ask the same questions as text with lettered options, for example "Left knee: how should the coach handle it? A) It's fine now: train normally, B) Go light and build back slowly, C) Avoid loading it for now". Wait for the answer.

## Writes

- `athlete/limits.md`: the line the athlete chose (a live answer only).
- `athlete/log/<YYYY-MM>.md`: one line for a region that is fine, a removed limit, or resolved old notes (and, from the calling skill, the "pain handled" line of step 9).
- `athlete/.urgent-stop` and `athlete/log/urgent-clearances.jsonl`, only through `node engine/cli.ts urgent set` and `node engine/cli.ts urgent clear --reason clinician|false-alarm`.

## Unattended

No one can answer, so ask nothing and change no line in `athlete/limits.md`. A check-in or a note that names pain: avoid loading that region today (an `annotate` note "Adjusted for recovery"), and write one log line "- proposal for the next live session: ask about <region>". An urgent sign: run `node engine/cli.ts urgent set --term <name> --source note` (or `checkin`); never clear the stop.
